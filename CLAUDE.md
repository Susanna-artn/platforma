# Платформа подготовки по математике и физике

## Что это
Веб-платформа для репетиторского проекта: 2 преподавателя (математика, физика),
10-30 учеников на старте, 9-11 классы, отдельные разделы ОГЭ и ЕГЭ.
Вся работа ученика идёт на сайте: решает задачи, вводит ответ или решение
по шагам, получает автоматическую проверку и разбор ошибок.
Преподаватель в кабинете видит историю ошибок каждого ученика и группы.
Недельная сводка приходит преподавателю и родителю в Telegram.

Главная ценность - не разовая проверка, а накопленная история ошибок
конкретного ученика по закрытой таксономии.

Это реальный продукт с реальными детьми, не демо.

## Как со мной работать
- Я начинающий разработчик. Объясняй решения коротко и по-русски:
  что делаешь, зачем, какие были варианты и почему выбран этот.
- Перед каждым этапом покажи план шагов и дождись моего "ок".
- После каждого шага скажи, как запустить и проверить результат руками.
- Новую зависимость добавляй только с объяснением, зачем она.
  Предпочитай стандартные и популярные библиотеки.
- Маленькие коммиты с понятными сообщениями на русском.
- Если моя просьба противоречит этому файлу или выглядит ошибкой - скажи прямо.
- Не делай то, что относится к следующим этапам, без моего запроса.
- В текстах интерфейса не используй длинное тире, только дефис.

## Стек
- web/ - Next.js (App Router), TypeScript, Tailwind CSS.
  Владеет базой, авторизацией и всей бизнес-логикой.
  ORM: Drizzle, миграции только через Drizzle.
  Авторизация: Auth.js, вход по логину и паролю.
  Формулы: KaTeX для отображения, MathLive для ввода.
- checker/ - Python 3.12, FastAPI, SymPy. Сервис без состояния:
  получает задачу и ответ/решение, возвращает вердикт в JSON.
  В базу не ходит. Здесь же вызовы ИИ.
- notifier/ - отправка сообщений в Telegram (TypeScript, grammY):
  привязка аккаунта по ссылке и недельные сводки. Больше ничего,
  ученики с ботом не работают.
- PostgreSQL 16. Всё поднимается через docker compose.
- Хостинг: российский VPS (данные учеников хранятся только в РФ, 152-ФЗ).
  Никаких зарубежных облачных баз и хранилищ.
- Загрузка фото и распознавание рукописи в текущую версию не входят.

## Роли
- admin - я. Пользователи, банк задач, импорт, настройки, лимиты.
- teacher - свои группы, домашние задания, очередь проверки,
  история ошибок учеников, таксономия своего предмета.
- student - задания, ввод ответов и решений, свои разборы, свой прогресс.
- parent - просмотр прогресса своего ребёнка на сайте и сводка в Telegram.
Аккаунты учеников создаёт преподаватель или admin (у детей часто нет почты).
Родитель подключается по одноразовой ссылке-приглашению.
Ученик работает только после отметки о согласии родителя.

## Банк задач
- Только собственные задачи. Никогда не импортировать и не копировать
  задачи из чужих банков и сайтов.
- Задача: предмет, класс (9-11), раздел/тема, опционально экзамен
  (ОГЭ/ЕГЭ, для математики ЕГЭ - база или профиль) и номер задания,
  сложность, условие в Markdown + LaTeX, тип ответа, эталонный ответ,
  единицы (физика), эталонное решение, критерии оценивания (для части 2).
- Типы ответа: number (с допуском), expression (эквивалентность),
  roots (множество корней), interval, tuple, quantity (число + единицы),
  digits (последовательность цифр, как в ОГЭ/ЕГЭ), steps (решение по шагам).
- Импорт пачкой из JSON по схеме в docs/task-schema.md
  с валидацией и отчётом об ошибках.

## Ввод решения по шагам
- Ученик вводит решение построчно: каждый шаг - формула (MathLive)
  и необязательный текстовый комментарий ("по теореме Виета", "ОДЗ").
- Шаги хранятся отдельно, в порядке, с исходным LaTeX и разобранным
  выражением.
- Если формулу шага не удалось разобрать, ученик видит это сразу
  при вводе, а не после отправки.

## Проверка
1. Короткий ответ проверяет только SymPy, ИИ не вызывается.
2. Решение по шагам: SymPy проверяет эквивалентность каждого перехода
   (для уравнений - равносильность, с учётом потери и приобретения корней,
   для физики - согласованность единиц) и находит первый неверный шаг.
3. ИИ вызывается только если есть ошибка или шаг не удалось проверить
   формально. Модель получает условие, шаги, номер проблемного шага
   и результат SymPy. Модель не решает задачу вместо проверки.
4. Ошибки классифицируются только кодами из таксономии в базе.
   Ответ модели - строгий JSON, валидируется схемой; невалидный ответ
   повторяется один раз, потом уходит преподавателю.
5. Разбор для ученика: какой шаг, какой тип ошибки, наводящий вопрос.
   Полное решение - после 2 неудачных попыток или по решению преподавателя
   (настройка задания).
6. Развёрнутые решения ОГЭ/ЕГЭ части 2: ИИ предлагает балл по критериям,
   финальный балл ставит преподаватель. Ученик видит балл только после
   подтверждения.
7. Любой вердикт ИИ помечается как предварительный и может быть
   исправлен преподавателем; исправления сохраняются.

## ИИ-провайдеры
- Все вызовы через интерфейс LLMProvider в checker/providers/.
  Реализации: yandex (Yandex AI Studio), gigachat. Выбор через .env.
- Каждый вызов логируется: провайдер, модель, токены, стоимость в рублях,
  задержка, ошибка.
- Лимиты: месячный на ученика и общий. При превышении ИИ не вызывается,
  решение уходит в очередь преподавателя.
- Промпты лежат в checker/prompts/ отдельными файлами с версией.

## Качество
- eval/dataset.json - эталонные набранные решения по шагам с разметкой
  преподавателя (верно/неверно, номер ошибочного шага, коды ошибок).
- eval/run.py прогоняет набор и пишет отчёт в eval/reports/:
  точность вердикта, точность номера шага, точность и полнота по кодам
  ошибок, стоимость, среднее время. Отдельно - что поймал SymPy,
  что поймала модель.
- После каждого изменения промпта или модели - повторный замер.

## Персональные данные
- Хранить минимум: имя и первую букву фамилии, класс, группа.
- Согласие родителя фиксируется с датой.
- Секреты только в .env, .env в .gitignore, есть .env.example.

2. Банк задач: модель данных, KaTeX, импорт JSON, страница задачи
