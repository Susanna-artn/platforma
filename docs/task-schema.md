# Формат импорта задач (JSON)

Задачи загружаются в банк файлом JSON через админку: "Задачи" -> "Импорт".
Перед импортом файл проверяется целиком. Если есть хоть одна ошибка,
не импортируется ничего. Импорт идёт одной транзакцией: либо весь файл,
либо ничего.

Только собственные задачи. Задачи из чужих банков и сайтов не импортируем.

Полный рабочий пример: [examples/tasks-example.json](examples/tasks-example.json).

## Структура файла

```json
{
  "topics": [ ... ],
  "tasks": [ ... ]
}
```

Оба раздела необязательны: можно загрузить только темы или только задачи
(если их темы уже есть в базе).

## Темы (`topics`)

Темы - это строгий справочник. По темам потом строится история ошибок,
поэтому задача ссылается на тему по коду, а не по названию.

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| `code` | строка | да | Код темы: латиница, цифры, точка, дефис, подчёркивание. Например `m.alg.quadratic` |
| `subject` | `"math"` или `"physics"` | да | Предмет |
| `section` | строка | да | Раздел, например "Алгебра" |
| `name` | строка | да | Тема, например "Квадратные уравнения" |

Если тема с таким кодом уже есть в базе, раздел и название обновляются.
Предмет у существующей темы поменять нельзя.

## Задачи (`tasks`)

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| `code` | строка | да | Уникальный код задачи, например `m9-quad-001`. Повторный импорт с тем же кодом обновляет задачу |
| `subject` | `"math"` или `"physics"` | да | Предмет |
| `grade` | 9, 10 или 11 | да | Класс |
| `topic` | строка | да | Код темы (из этого файла или уже из базы). Предмет темы должен совпадать с предметом задачи |
| `exam` | см. ниже | нет | Экзамен |
| `examTaskNumber` | целое 1-30 | нет | Номер задания в экзамене. Только вместе с `exam` |
| `examPart` | 1 или 2 | нет | Часть экзамена. Только вместе с `exam`. Для части 2 обязательны `criteria` |
| `difficulty` | 1, 2 или 3 | да | 1 - базовый, 2 - повышенный, 3 - высокий уровень |
| `status` | `"draft"`, `"published"`, `"archived"` | нет | Новая задача без статуса - черновик. У существующей без статуса статус не меняется |
| `statement` | строка | да | Условие: Markdown и формулы LaTeX (`$...$` в строке, `$$...$$` отдельной строкой) |
| `answer` | объект | да | Эталонный ответ, см. ниже |
| `solution` | строка | нет | Эталонное решение, Markdown + LaTeX |
| `criteria` | список | нет | Критерии оценивания, см. ниже |

Экзамены (`exam`):

| Значение | Что это | Предмет |
| --- | --- | --- |
| `oge` | ОГЭ | математика и физика |
| `ege_base` | ЕГЭ, база | только математика |
| `ege_profile` | ЕГЭ, профиль | только математика |
| `ege` | ЕГЭ | только физика |

Критерии (`criteria`) - список вариантов оценки:

```json
"criteria": [
  { "points": 2, "description": "Обоснованно получен верный ответ" },
  { "points": 1, "description": "Решение доведено до конца, но допущена вычислительная ошибка" },
  { "points": 0, "description": "Решение не соответствует ни одному из критериев выше" }
]
```

Максимальный балл задачи - наибольшее `points` в критериях.

### Картинки

Картинку сначала загружают в админке ("Картинки"), там же видна готовая
ссылка. В тексте условия или решения она вставляется как в Markdown:

```
![Схема цепи](/media/3f2a...9c.png)
```

При импорте проверяется, что все упомянутые картинки загружены.

## Эталонный ответ (`answer`)

Формулы в ответах пишутся не в LaTeX, а текстом, как в калькуляторе:
`2*x + 1`, `sqrt(2)/2`, `x**2` (степень - две звёздочки), `pi`, `oo` (бесконечность).
Их будет разбирать SymPy на этапе проверки.

Тип ответа задаётся полем `type`:

### `number` - число с допуском

```json
{ "type": "number", "value": 2.5, "tolerance": 0.01 }
```

- `value` - число;
- `tolerance` - допустимое отклонение по модулю (необязательно, по умолчанию 0);
- `relativeTolerance` - допустимое отклонение в долях от ответа, например 0.02 = 2%
  (необязательно). Можно указать что-то одно из двух.

### `expression` - выражение

```json
{ "type": "expression", "value": "(x - 1)*(x + 1)" }
```

Ответ ученика засчитывается, если он равен эталону как выражение.

### `roots` - множество корней

```json
{ "type": "roots", "values": ["2", "3"] }
```

Порядок не важен. Пустой список - "корней нет".

### `interval` - промежуток или объединение промежутков

```json
{ "type": "interval", "value": "(-oo; -1] U (2; 5)" }
```

Промежутки пишутся через ` U `. Концы разделяются точкой с запятой.
Скобки `(` `)` - конец не входит, `[` `]` - входит. Бесконечности: `-oo`, `+oo`.
Отдельная точка: `{3}`.

### `tuple` - упорядоченный набор

```json
{ "type": "tuple", "values": ["1", "-2"] }
```

Например, решение системы (x; y). Порядок важен.

### `quantity` - физическая величина

```json
{ "type": "quantity", "value": 12, "unit": "m/s", "relativeTolerance": 0.02 }
```

- `value` - число;
- `unit` - единицы латиницей в записи SymPy: `m`, `s`, `kg`, `N`, `J`, `W`, `Pa`,
  `V`, `A`, `ohm`, `K`, `m/s`, `m/s**2`, `kg*m**2` и так далее;
- `tolerance` / `relativeTolerance` - как у `number`.

### `digits` - последовательность цифр (как в бланке ОГЭ/ЕГЭ)

```json
{ "type": "digits", "value": "312", "ordered": true }
```

- `value` - только цифры;
- `ordered` - важен ли порядок (необязательно, по умолчанию `true`).
  Для заданий вида "выберите два верных утверждения" ставьте `false`.

### `steps` - решение по шагам

```json
{ "type": "steps", "final": { "type": "roots", "values": ["-1", "4"] } }
```

- `final` - итоговый ответ любого типа, кроме `steps` (необязательно:
  у доказательства итогового ответа нет).

## Пример задачи

```json
{
  "code": "m9-quad-001",
  "subject": "math",
  "grade": 9,
  "topic": "m.alg.quadratic",
  "exam": "oge",
  "examTaskNumber": 9,
  "examPart": 1,
  "difficulty": 1,
  "status": "published",
  "statement": "Решите уравнение $x^2 - 5x + 6 = 0$.",
  "answer": { "type": "roots", "values": ["2", "3"] },
  "solution": "По теореме Виета $x_1 + x_2 = 5$, $x_1 x_2 = 6$, откуда $x_1 = 2$, $x_2 = 3$."
}
```
